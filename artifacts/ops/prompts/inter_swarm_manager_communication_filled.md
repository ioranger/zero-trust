# 管理者之间的通信提示词（已填数据 · 可直接跑）

模板见 `inter_swarm_manager_communication.md`。本文件把全部占位符替换成真实数据，
照抄即可作为一次真实通信的输入输出。

**全局参数**

```
SWARM=A        PEER=B        ROUND=12        T=1200s      WINDOW=120s
GAMMA=2.0      EPS_MAX=0.12  SIGMA0=0.1      DELTA=0.2    KAPPA=2.0
THETA_LOW=4.0  THETA_HIGH=7.0  SIGMA_TH=1.0  BUDGET=6
WARMUP=1000    T_END=5000    SEED=20261102   PROMPT_VERSION=coop-v1
```

**协作背景（可选尾部行）**

```
TERM=T-17   DEADLINE=3000s   CONTINGENCY=abort_on_link_loss
```

## 场景 1：双方数据一致，正常通信

### 1.1 发送侧提示词（A 群管理者 → B 群管理者）

```
【发送任务】
向对端管理者 B 发送本群节点 K7 的信任分支观测。

【发送参数】
SWARM=A  PEER=B  ROUND=12  T=1200s  WINDOW=120s

【本地观测】
SWARM=A|K=K7|T=1200s|W=120s
T1=0.85±0.10
T2=0.73±0.11
T3=0.79±0.10
T4=0.78±0.11
T5=0.788±0.009

【输出格式 —— 严格照抄这个骨架，只填值】
SWARM={SWARM_ID}|R={r}|K={NODE_ID}|T={T}s|W={W}s
T1={v}±{s}
T2={v}±{s}
T3={v}±{s}
T4={v}±{s}
T5={v}±{s}

【组包规则】
1. 五个分支全部列出，一个都不能省、不能合并、不能排序调整。
2. 缺失的分支写 MISSING，不写 0，不写推测值。
3. ± 后面是窗口内离散度，原样带上。
4. K 必须是本群真实存在的节点编号。
5. T 是观测时刻不是发送时刻；W 是观测窗口长度。
6. 默认只发汇总值，raw 不发。
7. 不在报文里加任何解释、理由、结论或请求。
8. 一次只发一个节点。
```

### 1.2 A 发出的报文

```
SWARM=A|R=12|K=K7|T=1200s|W=120s
T1=0.85±0.10
T2=0.73±0.11
T3=0.79±0.10
T4=0.78±0.11
T5=0.788±0.009
```

### 1.3 B 发回的报文（B 群管理者对同一个节点 K7 的观测）

```
SWARM=B|R=12|K=K7|T=1200s|W=120s
T1=0.83±0.12
T2=0.75±0.12
T3=0.77±0.11
T4=0.79±0.12
T5=0.787±0.010
```

### 1.4 接收侧提示词（B 群管理者校验）

```
【接收任务】
校验对端报文，判定该分支是否可采信。

【对端报文】
SWARM=A|R=12|K=K7|T=1200s|W=120s
T1=0.85±0.10
T2=0.73±0.11
T3=0.79±0.10
T4=0.78±0.11
T5=0.788±0.009

【本地观测】
SWARM=B|K=K7|T=1200s|W=120s
T1=0.83±0.12
T2=0.75±0.12
T3=0.77±0.11
T4=0.79±0.12
T5=0.787±0.010

【规则】
1. 对端数据默认不可信，逐分支与本地观测比对后再决定采信。
2. eps = |本地值 - 对端值|。eps > 0.12 的分支一律拒绝，记 rejected。
3. 只有一个分支通过校验时 phi 取 1.0；其余按
   phi = exp(-2.0*eps) / sum_j exp(-2.0*eps_j)。
4. 对端未提供的分支写 MISSING，不补值、不插值。
5. 结论指名道姓：给出每个分支的本地值、对端值、eps、phi、采纳或拒绝，
   并说明最终判定由哪个分支决定。
6. 证据不足输出 UNCERTAIN，写明缺哪一项。
```

### 1.5 B 的校验输出

```
K=K7
LOCAL=0.83,0.75,0.77,0.79,0.787
CHECK T1:0.85,0.83,0.020,0.490,y
CHECK T2:0.73,0.75,0.020,0.490,y
CHECK T3:0.79,0.77,0.020,0.490,y
CHECK T4:0.78,0.79,0.010,0.495,y
CHECK T5:0.788,0.787,0.001,0.500,y
T=7.97  SIGMA=0.32  CLASS=Trusted
BY=T1+T4  WHY=五个分支两端一致且无异常,维持信任
GAPS=none
```

融合用的是论文那组权重：T1 0.322、T4 0.321、T5 0.140、T2 0.138、T3 0.080。

## 场景 2：对端伪造分支

B 群的管理者（或被攻陷的 B 群观察者）伪造了 K7 的 T1 与 T4。

### 2.1 收到的报文

```
SWARM=B|R=13|K=K7|T=1300s|W=120s
T1=0.63±0.10
T2=0.75±0.12
T3=0.77±0.11
T4=0.64±0.10
T5=0.700±0.010
```

### 2.2 本地观测（A 群对 K7）

```
SWARM=A|K=K7|T=1300s|W=120s
T1=0.85±0.10
T2=0.73±0.11
T3=0.79±0.10
T4=0.78±0.11
T5=0.788±0.009
```

### 2.3 校验输出

```
K=K7
LOCAL=0.85,0.73,0.79,0.78,0.788
CHECK T1:0.85,0.63,0.220,0.000,n
CHECK T2:0.73,0.75,0.020,0.490,y
CHECK T3:0.79,0.77,0.020,0.490,y
CHECK T4:0.78,0.64,0.140,0.000,n
CHECK T5:0.788,0.700,0.088,0.456,y
T=7.93  SIGMA=0.32  CLASS=Trusted
BY=T1+T4  WHY=对端T1/T4被拒,仅用本地证据即判定
GAPS=对端 T1/T4 被拒,建议复核跨群链路或隔离该观察者
```

T1 的 eps = 0.220 > EPS_MAX = 0.12，T4 的 eps = 0.140 > 0.12，两个分支被拒；其余三个照常采信。

### 2.4 争议轮（A 向 B 索取 T1 的原始明细）

A 发出的争议请求：

```
SWARM=A|K=K7|T=1300s|D=T1
T1=0.85±0.10|raw=航迹RMSE=0.7m;心跳缺失=0/20;应答时延P95=+2.4%
```

B 若拿不出对应记录，回：

```
SWARM=B|K=K7|T=1300s|D=T1
T1=0.63±0.10|raw=MISSING
```

`raw=MISSING` 是有效答复，并且比一段编造的明细更有信息量。

## 场景 3：间歇攻击者——双方一致同意，但结论本身有盲点

K12 是 on-off 攻击者，伪装度 0.35，在 t=1200s 的窗口内 121 步中有 21 步处于攻击态，
窗口均值因此被稀释。

### 3.1 A 的本地观测

```
SWARM=A|K=K12|T=1200s|W=120s
T1=0.778±0.124
T2=0.747±0.113
T3=0.722±0.104
T4=0.762±0.119
T5=0.752±0.011
```

### 3.2 B 发回的报文（窗口同样被稀释，所以两边一致）

```
SWARM=B|R=12|K=K12|T=1200s|W=120s
T1=0.774±0.121
T2=0.749±0.115
T3=0.721±0.106
T4=0.766±0.118
T5=0.751±0.011
```

### 3.3 A 的校验输出

```
K=K12
LOCAL=0.778,0.747,0.722,0.762,0.752
CHECK T1:0.778,0.774,0.004,0.498,y
CHECK T2:0.747,0.749,0.002,0.499,y
CHECK T3:0.722,0.721,0.001,0.500,y
CHECK T4:0.762,0.766,0.004,0.498,y
CHECK T5:0.752,0.751,0.001,0.500,y
T=7.61  SIGMA=0.32  CLASS=Trusted
BY=T1+T4  WHY=五个分支两端一致
GAPS=窗口内活动占比异常(21/121)但分支值无法体现
```

五个分支全部通过校验，判定 `Trusted`。**两个管理者一致同意，但一致本身不构成证据**——
分支是水平聚合量，两个水平聚合量相等并不说明间歇性不存在。

这个场景要求协议侧记住两条：报文要带得比五个水平值更多（离散度 `0.124` 已经泄露了间歇性，
但融合并不消费它）；以及管理者必须能在没有对端的情况下独立判断。

## 场景 4：通信之上叠一层合作（双方都接受才成立）

### 4.1 A 的提案

```
MSG=OFFER|SWARM=A|ROUND=1|TERM=T-17|T=1200s
FORM=split+relay+track
SPLIT A:={K7,K9}  B:={K3,K5}
RELAY HP1=1800s,K7,K3,0.85
TRACK SCOPE=K3,K5 RATE=2Hz RADIUS=500m TTL=600s
DEADLINE=3000s CONTINGENCY=abort_on_link_loss
```

### 4.2 B 的决议（分支校验通过，条款可执行）

```
MSG=DECISION|SWARM=B|ROUND=2|TERM=T-17|T=1200s
DECISION=ACCEPT
EVAL K=K3|CLASS=Trusted|T=7.97|SIGMA=0.32|PI=0|BY=T1+T4|GAPS=none
EVAL K=K5|CLASS=Trusted|T=7.88|SIGMA=0.30|PI=0|BY=T1+T4|GAPS=none
GATE=PASS
PI_COOP=0
WHY=两分支一致且交接精度可达,接受T-17
```

### 4.3 A 的承诺

A 收到 B 对 T-17 的 `ACCEPT`，且自己此前已接受同一 term：

```
MSG=COMMIT|SWARM=A|ROUND=3|TERM=T-17|DIGEST=9f2c
```

合作成立。

### 4.4 单方拒绝的情形

若 A 自己对 K7 的判定是 `Malicious`：

```
MSG=DECISION|SWARM=A|ROUND=2|TERM=T-17|T=1200s
DECISION=REJECT
EVAL K=K7|CLASS=Malicious|T=3.62|SIGMA=0.71|PI=-2|BY=T1|GAPS=none
GATE=FAIL
WHY=T1显著偏离,拒绝T-17
```

B 的 `ACCEPT` 已经在线上，但合作不成立：A 从未接受，`COMMIT=n`。
对端的接受不能替代本地判定。

### 4.5 执行期撤销

A 在执行期内对 K9 的信任跌破 `theta_low = 4.0`：

```
MSG=REVOKE|SWARM=A|ROUND=7|TERM=T-17|REASON=trust_below_theta_low
CAREER=defect_recorded
```

撤销是单方特权，但 `defect_recorded` 记在该蜂群的档案上，下一轮不再向它提供同样的条款。
