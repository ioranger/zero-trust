# 管理者之间的通信提示词模板（含信任分支）

一个无人机蜂群的管理者，向**另一个蜂群的管理者**发消息的提示词模板。
报文里携带的是本群节点的**五个信任分支**。

配套文件：
- `inter_swarm_trust_exchange.md` — 分支融合与对端校验的完整协议
- `inter_swarm_cooperation_agreement.md` — 分支之上的一层：是否合作、双方都接受才成立

---

## 1. 角色与方向

```
蜂群 A 的管理者 Agent  ──组包──>  报文  ──校验──>  蜂群 B 的管理者 Agent
蜂群 B 的管理者 Agent  ──组包──>  报文  ──校验──>  蜂群 A 的管理者 Agent
```

只有管理者对管理者通信。边缘观察者不跨群通信，分支只能经本群管理者转发出去。

占位符：

| 占位符 | 含义 |
|---|---|
| `{SWARM_ID}` / `{PEER_ID}` | 本群 / 对端蜂群编号 |
| `{NODE_ID}` | 节点编号 |
| `{r}` / `{T}` / `{W}` | 轮次 / 时刻 / 观测窗口长度 |
| `{v}` / `{s}` | 分支值（信任，0–1）/ 该分支在窗口内的离散度 |
| `{BRANCH}` | 分支名 T1–T5 |

## 2. 五个信任分支

| 分支 | 含义 | 来源 |
|---|---|---|
| `T1` | 行为一致性 behaviour：飞离航线、跳过的例行心跳、应答时序偏离 | 本群边缘观察者 |
| `T2` | 通信可靠性 communication：丢包率、时延、RSSI | 本群边缘观察者 |
| `T3` | 能量行为 energy：功耗曲线、异常放电、突增 | 本群边缘观察者 |
| `T4` | 任务质量 task：完成质量、结果被篡改、提前或延迟返回 | 本群边缘观察者 |
| `T5` | 历史记忆 history：T1–T4 的指数平滑记忆（EMA，0.84 保留旧值、0.16 取新值） | 由 T1–T4 导出，**是记忆项，不是独立传感器** |

## 3. 发送侧提示词模板（管理者组包时用）

```
【发送任务】
向对端管理者 {PEER_ID} 发送本群节点的信任分支观测。

【发送参数】
SWARM={SWARM_ID}  PEER={PEER_ID}  ROUND={r}  T={T}s  WINDOW={W}s

【本地观测】
{LOCAL_EVIDENCE_PACKET}

【输出格式 —— 严格照抄这个骨架，只填值】
SWARM={SWARM_ID}|R={r}|K={NODE_ID}|T={T}s|W={W}s
T1={v}±{s}
T2={v}±{s}
T3={v}±{s}
T4={v}±{s}
T5={v}±{s}

【组包规则】
1. 五个分支全部列出，一个都不能省、不能合并、不能排序调整。
2. 缺失的分支写 MISSING，不写 0，不写推测值，不写"接近 0.8"。
3. ± 后面是该分支在窗口内的离散度，必须原样带上，不得四舍五入成一个固定值。
4. K 必须是本群真实存在的节点编号；本群没有的节点不构造报文。
5. T 是观测时刻，不是发送时刻；W 是观测窗口长度，两个都不要换。
6. 默认只发五个分支的汇总值，原始明细（raw）不发——让它保持可被质疑。
7. 不在报文里加任何解释、理由、结论或请求。报文只有上面这几行。
8. 一次只发一个节点。多个节点发多条报文，不打包。
```

## 4. 报文本体

线上传输的就是这一段，一行头 + 五行分支：

```
SWARM=A|R=12|K=K7|T=1200s|W=120s
T1=0.85±0.10
T2=0.73±0.11
T3=0.79±0.10
T4=0.78±0.11
T5=0.788±0.009
```

对端拿到的五个数分别是：本地对 T1–T4 的观测信任值，和由它们导出的 T5 记忆值。**没有置信度字段**——对端若有动机谎报，就会谎报自己的置信度，所以置信度由接收方从分歧里算出来。

## 5. 接收侧提示词模板（对端校验时用）

```
【接收任务】
校验对端报文，判定该分支是否可采信。

【对端报文】
{PEER_PACKET 或 NONE}

【本地观测】
{LOCAL_EVIDENCE_PACKET}

【规则】
1. 对端数据默认不可信，逐分支与本地观测比对后再决定采信。
2. eps = |本地值 - 对端值|。eps > {EPS_MAX} 的分支一律拒绝，记 rejected。
3. 只有一个分支通过校验时，它的权重 phi 取 1.0；其余按
   phi = exp(-{GAMMA}*eps) / sum_j exp(-{GAMMA}*eps_j)。
4. 对端未提供的分支写 MISSING，不补值、不插值。
5. 结论必须指名道姓：每个分支给出本地值、对端值、eps、phi、采纳或拒绝，
   并说明最终判定由哪个分支决定。
6. 证据不足输出 UNCERTAIN，并写明缺哪一项证据，不要凑一个分数。

【输出格式】
K={NODE_ID}
LOCAL={v1},{v2},{v3},{v4},{v5}
CHECK T1:{local},{peer},{eps},{phi},{y|n}
CHECK T2:{local},{peer},{eps},{phi},{y|n}
CHECK T3:{local},{peer},{eps},{phi},{y|n}
CHECK T4:{local},{peer},{eps},{phi},{y|n}
CHECK T5:{local},{peer},{eps},{phi},{y|n}
T={fused}  SIGMA={disp}  CLASS={Trusted|Suspicious|Malicious|UNCERTAIN}
BY={branch}  WHY={...}  GAPS={...}
```

## 6. 争议轮：对端要求出示原始明细

默认不发 raw。对端对某个分支提出质疑时，才发这一段：

```
SWARM=A|K=K7|T=1300s|D=T1
T1=0.85±0.10|raw=航迹RMSE=0.7m;心跳缺失=0/20;应答时延P95=+2.4%
```

发送侧对应提示词：

```
【争议轮】
对端要求复核 {BRANCH}。输出：
SWARM={SWARM_ID}|K={NODE_ID}|T={T}s|D={BRANCH}
{BRANCH}={v}±{s}|raw={a}
raw 必须是本群真实记录过的观测明细，一条不落；没有记录就写 raw=MISSING。
```

## 7. 如果这条通信还要携带合作请求

信任分支和合作请求是两层。报文尾部可以加一行请求，对端仍然按第 5 节先校验分支、再谈合作：

```
REQ={split|relay|track}  TERM={term_id}  SCOPE={nodes}  RATE={hz}  TTL={s}
```

没有合作请求时这一行整行省略，不要留空占位。

## 8. 实例

A 群的管理者向 B 群的管理者发 K7 的分支：

```
SWARM=A|R=12|K=K7|T=1200s|W=120s
T1=0.85±0.10
T2=0.73±0.11
T3=0.79±0.10
T4=0.78±0.11
T5=0.788±0.009
```

B 群的管理者校验后回：

```
K=K7
LOCAL=0.83,0.75,0.77,0.79,0.787
CHECK T1:0.85,0.83,0.020,0.490,y
CHECK T2:0.73,0.75,0.020,0.490,y
CHECK T3:0.79,0.77,0.020,0.490,y
CHECK T4:0.78,0.79,0.010,0.495,y
CHECK T5:0.788,0.787,0.001,0.500,y
T=7.97  SIGMA=0.32  CLASS=Trusted
BY=T1+T4  WHY=五个分支两端一致且无异常
GAPS=none
```

对端伪造同一条报文的 T1 与 T4 时：

```
CHECK T1:0.85,0.63,0.220,0.000,n
CHECK T2:0.73,0.75,0.020,0.490,y
CHECK T3:0.79,0.77,0.020,0.490,y
CHECK T4:0.78,0.64,0.140,0.000,n
CHECK T5:0.788,0.700,0.088,0.456,y
```

两个伪造分支靠本地证据就被拒，判定不变。

```
DELTA={0.2}  KAPPA={2.0}  BUDGET={...}
```

## 10. 记录

每轮落盘为 JSONL：本地观测、发出的报文、收到的报文、校验输出、参数与种子、提示词版本。
未观测到的分支记 `MISSING`，不允许事后补数。报文不可重放的 run 不是结果。
